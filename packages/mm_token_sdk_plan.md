# MM Token SDK Plan

## Goal

Support the KGW `mm_token` bearer authenticator from idos-sdk-js without changing normal action usage. A client receives an envelope:

```json
{
  "token": "base64url(original-token-json-bytes)",
  "signature": "base64url(ed25519-signature-over-original-token-json-bytes)"
}
```

The decoded token JSON contains `signing_public_key` as a base64url 32-byte Ed25519 public key. KGW expects:

- auth type: `mm_token`
- signer identity / compact ID: decoded `signing_public_key` bytes
- signature bytes: UTF-8 JSON bytes of the envelope

After `kwilClient.setSigner(mmSigner)`, existing `kwilClient.call(...)` and `kwilClient.execute(...)` calls should remain unchanged.

### Validated against `idos-kgw/idos-kwild`

Confirmed against `testdata/schema.sql` and `extensions/auth/mm_token_auth_extension.go`:

- `MmTokenAuthenticator.Verify(sender, msg, signatureData)` ignores `msg` entirely and only parses/verifies `signatureData` — this is why `signMessage` must always return the static envelope bytes regardless of what message kwil-js asks it to sign.
- `MmTokenAuthenticator.Identifier(sender)` requires `sender` to be exactly `ed25519.PublicKeySize` (32) raw bytes and computes `@caller` as `base64.RawURLEncoding.EncodeToString(sender)` (unpadded base64url) — i.e. exactly `token.signing_public_key`. The identifier passed into `KwilSigner` must be those raw bytes.
- `-- for MM type, address and public key are the same, it's the mm_token signing_public_key in base64url format` (schema.sql) — this is not a UX choice, it's mandatory for both `address` and `public_key`.
- `caller_user_id()` and every DWG/access-grant lookup match `MM` wallets by `public_key = @caller` (like `NEAR`/`FaceSign`), not by `address`.

### Implementation gotcha

`KwilSigner`'s constructor treats a **string** identifier as hex via `hexToBytes(identifier)`; it only treats `Uint8Array` as raw bytes. Every other signer factory in `create-kwil-signer.ts` (FaceSign, NEAR, EVM) passes a **string** identifier because those wallet types are hex/native-address based. The MM signer must pass the **decoded raw bytes** (`Uint8Array`), never the base64url string — passing the string would get silently mangled by `hexToBytes` and produce the wrong `@caller`.

## Implementation Steps

1. Add a base64url codec helper.
   - No base64url (only standard padded base64) exists anywhere in the codebase today (`@idos-network/utils/codecs` wraps `@stablelib/base64`'s `encode`/`decode`).
   - `@stablelib/base64` is already a dependency and also exports `encodeURLSafe`/`decodeURLSafe`; its decoder correctly handles Go's unpadded `base64.RawURLEncoding` output for typical key/signature lengths. Reuse it — no new dependency needed.
   - Add `base64UrlEncode`/`base64UrlDecode` to `utils/codecs` alongside the existing `bs58Encode`/`hexDecode` helpers.

2. Add an MM token signer factory in `kwil-infra/src/create-kwil-signer.ts` or a focused new file such as `kwil-infra/src/mm-token/create-mm-token-kwil-signer.ts`.
   - Input: envelope JSON string or parsed envelope object.
   - Decode `envelope.token` using base64url.
   - Parse the decoded token JSON.
   - Decode `token.signing_public_key` using base64url to bytes; validate it's exactly 32 bytes (ed25519 public key size) before use.
   - Return `new KwilSigner(async (_msg: Uint8Array) => envelopeBytes, signingPublicKeyBytes, "mm_token")`.
   - **`signingPublicKeyBytes` must be passed as `Uint8Array`, never as a string** — see "Implementation gotcha" above.
   - Preserve the exact envelope bytes returned by `signMessage` (don't re-serialize the parsed object).

3. Export the factory from `kwil-infra/src/index.ts`.

4. Thread `MM` through SDK wallet types.
   - Add `"MM"` to `WALLET_TYPES` in generated action metadata (`kwil-infra/src/actions/actions.ts`, header says "generated by the generator, do not edit manually" — locate and rerun that generator against the updated schema; if unavailable, hand-patch with a comment flagging it needs regeneration).
   - Add an `"MM"` case to the `verifySignature` dispatcher in `kwil-infra/src/signature-verification/index.ts` (currently `default: throw new Error("Unsupported wallet type: ...")`) — schema.sql skips `idos.is_wallet_valid` entirely for `MM`, so this should likely be a no-op success.
   - Keep public self-registration unsupported: schema.sql rejects `add_wallet(..., "MM", ...)` via the wallet-type check, **and separately** rejects _any_ `add_wallet`/`remove_wallet` call when `@authenticator = 'mm_token'`, regardless of the wallet type being added/removed.

5. Support trusted inserter creation of `MM` wallets.
   - Ensure `upsertWalletAsInserter` accepts `wallet_type: "MM"`.
   - Set both `address` and `public_key` to `token.signing_public_key` (mandatory per schema comment, not a UX choice).

6. Add tests.
   - Construct a signer from an envelope and assert auth type is `mm_token`.
   - Assert signer identity bytes equal decoded `signing_public_key` (as raw bytes, not the base64url string).
   - Assert `signMessage` returns the exact envelope bytes.
   - Mock/integration test a generated read wrapper using `kwilClient.call` with the signer.
   - Mock/integration test a generated write wrapper using `kwilClient.execute` with the signer.
   - Test invalid envelope/token base64 produces a clear error.
   - Test `signing_public_key` of the wrong length produces a clear error.
   - Test that `add_wallet`/`remove_wallet` are rejected when called with an `mm_token`-authenticated signer (mirrors `Test_addWallet_RejectsMmAuthenticator`/`Test_removeWallet_RejectsMmAuthenticator` in `idos-kwild/schematest/mm_wallet_test.go`).

## Example Usage

```ts
import { createMmTokenAuth } from "@idos-network/kwil-infra";

const mmAuth = createMmTokenAuth(mmTokenEnvelope);
kwilClient.setSigner(mmAuth);

await getCredentials(kwilClient);
await removeCredential(kwilClient, { id });
```
